# 로또

## 이번 미션 목표
- 기능 단위를 명확히 정의하고 UI 로직과 도메인 로직을 분리한다.
- 예외 상황을 빠짐없이 정의하고 `IllegalArgumentException` 기반으로 방어 로직을 구성한다.
- JUnit5 + AssertJ 테스트를 작성해 기능 목록별로 동작을 검증한다.

## 새로운 도전 과제
- **스트림 기반 집계**: 명령형 루프 대신 `Stream`/`Collectors` 로 구현해 함수형 스타일을 연습한다.

## 구현 체크리스트
단계별 구현 항목을 완료할 때마다 체크하여 진행 상황을 추적합니다.

### 1. 프로젝트 준비
- [x] 로또 번호 범위, 구매 단가, 당첨 금액 등을 각 도메인 객체에 적절히 배치하여 의미 있게 관리한다.
- [x] 당첨 등수 조건과 상금을 Enum으로 구성하고 일치 개수/보너스 여부로 등수를 찾는 로직을 구현한다.
- [x] 핵심 도메인 객체(예: `Lotto`, `LottoTicket`, `WinningNumbers`)의 역할과 협력을 구체화한다.
- [x] 준비 단계 로직의 기본 단위 테스트를 작성해 구조가 의도대로 동작하는지 확인한다.

### 2. 입력 처리
- [ ] 구매 금액 입력 시 숫자 여부, 양수 여부, 1,000원 배수 여부를 검증하고 실패 시 `[ERROR]` 메시지와 함께 `IllegalArgumentException` 을 던진다.
- [ ] 검증 로직별 단위 테스트를 작성해 정상,예외 케이스를 확인한다.
- [ ] 당첨 번호를 쉼표 기준으로 분리해 6개인지, 중복이 없는지, 모두 1~45 범위인지 확인한다.
- [ ] 당첨 번호 검증 로직에 대한 테스트를 작성한다.
- [ ] 보너스 번호를 정수로 파싱하고 1~45 범위인지, 당첨 번호와 중복되지 않는지 검증한다.
- [ ] 보너스 번호 검증 테스트를 작성해 중복, 범위 오류를 검증한다.
- [ ] 입력 검증 실패 시 해당 단계부터 다시 입력을 받도록 인터페이스 계층을 분리한다.

### 3. 로또 발행
- [ ] 구매 금액으로 발행해야 할 로또 장 수를 계산한다.
- [ ] 발행 수 계산 로직에 대한 단위 테스트를 작성한다.
- [ ] `Randoms.pickUniqueNumbersInRange(1, 45, 6)` 으로 로또 한 장을 생성하고 오름차순으로 정렬한다.
- [ ] 로또 번호 범위, 중복 여부, 정렬을 검증하는 테스트를 작성한다.
- [ ] 생성된 로또들을 컬렉션으로 보관하고 발행 개수와 번호 목록을 출력 형식에 맞게 노출한다.

### 4. 당첨 결과 계산
- [ ] 구매한 각 로또와 당첨 번호를 비교해 일치 개수를 계산한다.
- [ ] 일치 개수 계산 로직에 대한 테스트를 작성한다.
- [ ] 일치 개수와 보너스 번호 일치 여부로 Enum 등수를 조회하고 당첨 횟수를 누적한다.
- [ ] 등수 판별과 누적 로직을 매개변수화 테스트로 검증한다.
- [ ] 등수별 상금을 합산해 총 수익을 계산하고, 구매 금액 대비 수익률을 소수점 둘째 자리에서 반올림한다.
- [ ] 수익률 계산 로직의 단위 테스트를 작성한다.

### 5. 결과 출력
- [ ] 당첨 통계 헤더와 구분선을 출력한다.
- [ ] 출력 메시지 포맷을 검증하는 테스트(문자열 Formatter 테스트)를 작성한다.
- [ ] 등수별로 `x개 일치 (상금) - y개` 형식의 문구를 출력한다.
- [ ] 총 수익률을 `총 수익률은 n%입니다.` 형식으로 출력한다.

### 6. 예외 및 흐름 제어
- [ ] 입력 단계에서 발생한 예외를 캐치해 `[ERROR]` 메시지를 출력하고, 해당 입력부터 다시 수행하도록 제어한다.
- [ ] 예외 발생 시 재시도 흐름이 유지되는지 시나리오 테스트를 작성한다.
- [ ] 애플리케이션의 비정상 종료를 방지하기 위해 `IllegalStateException` 등의 명시적인 예외만 사용한다.
- [ ] 상태 초기화 로직이 정상 동작하는지 테스트한다.

## 테스트 전략
- 기능 구현 직후 단위 테스트를 작성해 빠른 피드백을 확보한다.
- 도메인 로직을 대상으로 단위 테스트를 작성해 입력/당첨 통계 로직을 검증한다.
- 경계값(1, 45), 중복 번호, 잘못된 포맷 등 예외 케이스 테스트를 우선 작성한다.
- UI 입출력(`System.out`, `Console.readLine`) 로직은 제외하고 테스트한다.
